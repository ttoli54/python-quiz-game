# 한국 영화 퀴즈 게임 설계

## 의도

Python 초보자가 콘솔에서 한국 영화 퀴즈를 풀고, 직접 문제를 추가하며, JSON 파일 저장과 Git 기능을 함께 연습할 수 있는 작은 프로그램을 만든다. 기본 과제의 메뉴·클래스·입력 검증·영속 저장 요구를 충족하고, 사용자가 요청한 보너스 기능까지 하나의 일관된 흐름으로 제공한다.

## 목표

- 4지선다 한국 영화 퀴즈를 기본 6문제 제공한다.
- 퀴즈 풀기, 문제 추가, 목록 보기, 점수 확인, 종료 메뉴를 제공한다.
- 랜덤 출제, 문제 수 선택, 힌트와 점수 차감, 문제 삭제, 전체 게임 기록 저장을 제공한다.
- `state.json`을 UTF-8로 사용해 문제·최고 점수·게임 기록을 재실행 후에도 보존한다.
- 초보자가 읽을 수 있도록 역할이 분리된 4개 Python 파일과 README를 만든다.
- 실제 기능이 추가될 때마다 의미 있는 Git 커밋을 남기고, 기능 브랜치 병합과 clone/pull 실습 기록을 남긴다.

## 비목표

- 외부 Python 패키지나 데이터베이스 사용
- 그래픽 사용자 인터페이스 또는 웹 서버
- 사용자의 GitHub 계정으로 저장소를 생성하거나 공개·푸시하는 외부 작업의 자동 실행

## 실패로 보는 경우

- 입력 오류나 손상된 JSON 때문에 프로그램이 traceback으로 종료되는 경우
- 보너스 기능이 기본 기능과 충돌해 초보자가 메뉴 흐름을 이해하기 어려운 경우
- 실제로 확인하지 않은 Git 커밋·테스트·GitHub 결과를 README에 적는 경우

## 접근 방식

### 접근 1: 단일 파일 구현

`main.py` 한 파일에 모델과 게임을 모두 둔다. 가장 빠르지만 저장, 입력, 게임 진행이 섞여 보너스 기능이 늘어날수록 초보자가 책임을 구분하기 어렵다.

### 접근 2: 역할별 모듈 분리 — 선택

`quiz.py`는 한 문제의 데이터와 힌트·정답 검사를, `storage.py`는 JSON 읽기·쓰기를, `game.py`는 메뉴·게임 흐름·보너스를, `main.py`는 실행 진입점을 담당한다. 표준 라이브러리만 사용하면서 기능별 테스트와 README 설명을 쉽게 할 수 있으므로 선택한다.

### 접근 3: 보너스별 기능 브랜치 개발

기본 기능을 먼저 main에 완성하고 보너스 기능을 여러 브랜치로 나눠 병합한다. Git 학습에는 좋지만 이 작은 과제에는 브랜치 수가 과도해질 수 있으므로, 하나의 `bonus-features` 브랜치에서 보너스를 구현하고 main에 병합하는 수준으로 사용한다.

## 설계

### 파일 구조

```text
python-quiz-game/
├── main.py
├── quiz.py
├── storage.py
├── game.py
├── state.json
├── README.md
├── .gitignore
├── tests/
│   └── test_quiz_game.py
└── docs/superpowers/
    ├── plans/
    └── specs/
```

### `Quiz`

`Quiz(question: str, choices: list[str], answer: int, hint: str)`는 문제, 보기 4개, 1~4 정답 번호, 힌트를 가진다. `display()`, `is_correct(choice: int)`, `to_dict()`, `from_dict()`로 표시·채점·JSON 변환을 담당한다.

### `QuizGame`

게임 객체는 `quizzes`, `best_score`, `history`를 보유한다. 메뉴 표시, 입력 검증, 랜덤 문제 선택, 문제 수 선택, 힌트 사용과 감점, 문제 추가·삭제, 목록·점수 표시, 게임 기록 생성, 안전 종료를 담당한다. 랜덤 출제는 `random.sample()`로 현재 문제 목록을 섞고 선택한 수만큼 뽑는다.

힌트를 사용한 문제는 해당 문제에서 얻는 점수를 1점 차감한다. 점수는 `max(0, correct - hint_count)`로 계산하여 음수가 되지 않게 한다. 각 기록에는 실행 시각(ISO 8601 문자열), 푼 문제 수, 정답 수, 힌트 수, 점수를 저장한다.

### 저장 정책

`storage.py`는 다음 스키마를 관리한다.

```json
{
  "quizzes": [],
  "best_score": 0,
  "history": []
}
```

파일이 없으면 기본 퀴즈로 초기화한다. JSON이 손상되었거나 필수 구조가 잘못되면 안내 메시지를 출력하고 기본 상태로 복구한다. 저장 실패는 예외를 잡아 사용자에게 알리며, 가능한 경우 현재 메모리 상태로 프로그램을 계속 실행한다.

### 입력 및 종료 정책

모든 숫자 입력은 앞뒤 공백을 제거하고 빈 값·문자·허용 범위 밖 숫자를 재입력시킨다. 문제 텍스트와 보기도 빈 값을 허용하지 않는다. `KeyboardInterrupt`와 `EOFError`는 안내 메시지를 표시하고 현재 상태를 저장한 뒤 안전하게 종료한다.

### Git 및 증빙

실제 변경에 맞춰 10개 이상의 의미 있는 커밋을 만든다. 기본 기능과 보너스는 기능 브랜치에서 작업하고 `main`에 병합한다. GitHub 원격 작업은 사용자가 로그인·저장소 생성·푸시를 승인하고 실행할 수 있을 때만 진행하며, clone과 pull은 별도 복사본에서 실제로 수행한 뒤 README에는 확인된 결과만 기록한다.

## 남은 구현 작업

1. 프로젝트 초기 파일과 테스트 뼈대를 만든다.
2. `Quiz`, 저장소, 기본 문제와 게임 메뉴를 단계적으로 구현한다.
3. 기본 기능을 테스트하고 의미 있는 커밋을 만든다.
4. 기능 브랜치에서 다섯 가지 보너스를 구현하고 병합한다.
5. 오류·재실행·손상 JSON·전체 테스트를 확인한다.
6. 실제 확인 결과를 반영한 README와 Git 증빙을 작성한다.
